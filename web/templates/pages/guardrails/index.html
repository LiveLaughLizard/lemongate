{{icon "info" "opacity-60"}} How policies are applied

  • Default-on policies run on every request, for every key.
  • Attached policies run for the keys and teams that select them (key and team forms → Guardrail policies).
  • Per request, callers can opt in by name. The field accepts policy and guardrail names.
  • Disabled policies are ignored everywhere. Each guardrail runs at most once per call, even if several policies include it.

{{icon "info" "opacity-60"}} How guardrails are applied

  • Which run. Every enabled default-on guardrail and policy, plus those attached to the calling key or its team, plus any named in the request body: "guardrails": ["name"].
  • When. Pre checks request text (messages, prompt, input) before the model is called. Post checks generated text. Streamed responses can only be logged, never blocked or masked.
  • Order. Cheap checks run first (length, tool policy, blocklist, regex, code, PII, injection), model-backed checks last. Masking rewrites the text in place, so later guardrails and the model only see the masked version.
